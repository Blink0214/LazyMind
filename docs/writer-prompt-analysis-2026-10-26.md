# Writer 阶段输入与真实样例测量（2026-10-26）

本轮改为按职责组装输入，不再通过跨字段内容相等来决定删减。F5 使用现有 material_kind 路由，并未新增上传材料分类或结构化解析。参考材料和 analysis.findings 原文完整保留。

## 实现边界

- F5 大纲：已有大纲、图表目录从 context 各提供一次，query 只追加图表归属要求，不附加目录或大纲副本。
- 章节规划：outline 从专用参数提供，context 不装入 outline/manuscript。当前公共 Writer 章节规划为确定性代码，模型调用数为 0。
- 章节正文：context 提供完整研究材料、图表目录及全篇标题结构；当前章节指令提供局部目标、预算和关系。
- 修订规划：原稿从 document 参数提供；局部修订内容生成保留全局原稿背景，避免单段路径丢失上下文。
- 公共章节构建不再将 required_points 同时复制到 expected_blocks；显式调用方提供的局部约束原样保留。图片使用要求的章节作用域规则保留。
- 图表目录只保留 id/title/caption/columns/finding_ids，禁止复制 analysis 中完整 findings。未知 finding_ids 仍报错。
- 章节缓存对实际 task/context/instruction 输入计算指纹，不再用文本去重投影；有效局部要求变化仍使缓存失效。
- 未变更 F1—F4、F6；没有修改历史会话产物。

## 测量方法和限制

使用本地真实会话中的任务、材料池、大纲、稿件以及修订计划，离线调用当前 Writer 提示词组装路径，在模板格式化时捕获输入。没有请求模型或重新生成文章；并非线上 token 或耗时统计。字数为 Python 字符数，包含 Writer 模板及结构化输出的 system/schema，不含提供方隐藏消息、传输包装、失败重试。各占比之和可因四舍五入略有误差。

大材料 F5 来自历史会话，包含结构化分析和 7 章大纲；旧大纲没有当前图表归属标记，测量显式启用 --unbound-historical-outline，未计章节图表放置指令。不能视为当前完整工作流验收。小材料 F5 使用较新会话，执行图表绑定和章节预算组装。基础写作样例为真实“台风天安全防范指南，500—700字”请求；任务与大纲、正文按 task_id/context_id 核对关联。

各阶段为输入复放场景，不代表全部阶段都会在同一任务执行。特别是全文一次生成与分章生成是替代路径；基础写作该字数范围当前走全文路径。大纲统计包含 F5 的图表归属与保留既有结构指令；表示需要生成/补全大纲时的输入，已确认且图表归属完整时实际会跳过该调用；修订定位复用任务文本的行只用于大小诊断。单独的 saved_revision 行来自真实修订请求及计划，是历史保存输入经当前公共 Writer 序列化后的基线，未重新执行 F5 材料准备。

## 下一步是否值得做

值得，但应分两条路线：

1. 大材料 F5：优先为结构化 analysis 建立显式章节引用，以 finding_id/target_id/table_id 组织完整对象及依赖。章节绑定图表时 finding_ids 是确定性线索；还要同时带齐计算、来源、样本量、区间、对应诊断、限制和反面证据。未分配对象保持全局，不按关键词猜测后丢弃。先验证覆盖率，再考虑减少传输。
2. 小材料 F5：task 中约 1.27 万字符主要是论文通用规则，比材料更大。下一步更值得按大纲/写作/定位/检查拆分规则，保留所有与该阶段正确性有关的限制，论文规则继续由 F5 拥有。
3. 基础写作：大纲固定模板占约 82%，全文阶段章节指令占约 52%；优先审查阶段模板和章节指令格式。此样例不是参考材料选择的优先对象。
4. 原文 writing_materials：仍完整保留，不自动分类、截断或摘要替换。只有用户明确指定章节用途，或存在可核对的结构化关联时，才建议进一步分配。

以上材料分配和规则拆分仅为建议，本轮未实施语义选材。质量检查、引用/图表绑定、修订边界校验保留。
