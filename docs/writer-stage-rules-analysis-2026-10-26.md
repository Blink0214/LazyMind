# F5 阶段规则与图表 ID 选材测量（2026-10-26）

本轮生产修改只拆分 F5 固定规则；材料筛选仅在离线测量脚本中执行，未接入写作。未调用模型，未增加 LLM 选材。保留全部事实、引用和质量检查。

## 测量口径

使用实际保存的 F5 会话 pool 和已确认大纲（内容本身标注为模拟研究），严格验证大纲上下文与 pool 的 analysis 完全一致。共 7 章、4 张图、42 条 findings，其中 30 条被图表 ID 关联，12 条未关联。路径、逐项占比和 ID 明细见同目录 measurements JSON。

统计实际 Writer 模板渲染后的字符数，包含结构化输出 schema（适用时），不是 token、耗时或质量实验。固定规则前后使用相同材料与章节指令。大纲行是需要调用大纲模型时的提示词；已确认且图表归属完整时生产会跳过该调用。section_plan 为程序执行，模型调用为零。whole_document 不是本次 F5 主路径；revision_locate 行使用写作样例作模板诊断，不作为真实修订性能结论。

## 已实施的规则拆分

基础任务仅保存用户请求和有效约束；stage_task 在调用前直接组装共同规则和当前阶段规则，没有先重复加入再删除。大纲保留材料解释与结构规划；定位只保留定位和修订边界；正文保留完整事实、引用、写作规则和新稿图表规则；修订规划和执行使用修订图表规则及已选审稿意见；审核保留完整证据与引用检查规则。公共 Writer 和基础写作未加入论文专属规则。各阶段调用传入真实阶段 task，沿用有效输入 checkpoint 机制。

| 阶段 | 修改前完整输入 | 修改后完整输入 | 减少 |
|---|---:|---:|---:|
| 大纲 | 140,127 | 134,515 | 4.00% |
| 审核（固定同一上下文测量） | 174,602 | 174,320 | 0.16% |
| 7 章正文合计 | 934,750 | 933,497 | 0.13% |

正文每章仅减少 179 字符：事实、引用和写作要求仍然必要，因此规则拆分不能解决大材料的主体开销。

## 图表归属筛选候选：仅测量，不上线

每章保留该章图表关联的完整 finding 对象，以及全部未关联 findings；其余 analysis 字段、参考文献、其他材料全部保留。不截断对象，不用摘要代替事实。

| 章节 | 保留 findings | 完整输入 | 筛选候选输入 | 减少 |
|---|---:|---:|---:|---:|
| 摘要 | 12/42 | 132,811 | 69,020 | 48.03% |
| 引言 | 12/42 | 133,206 | 69,415 | 47.89% |
| 研究设计与方法 | 12/42 | 133,540 | 69,749 | 47.77% |
| 分类性能结果 | 24/42 | 133,590 | 98,568 | 26.22% |
| 模型规模与训练成本 | 30/42 | 133,477 | 104,708 | 21.55% |
| 综合讨论 | 12/42 | 133,588 | 69,797 | 47.75% |
| 结论与局限 | 12/42 | 133,285 | 69,494 | 47.86% |
| 合计 | — | 933,497 | 550,751 | 41.00% |

**这是仅按图表放置关系筛选的体积空间，不是可安全落地的收益。** 摘要、综合讨论和结论没有图表归属，但需要研究结果。分类性能章节也可能需要 accuracy_mean，而这些均值恰好关联在另一章节的权衡图上。全部章节的 ID 并集覆盖不能证明单章上下文足够。现有图表归属只能证明必须携带哪些 finding，不能证明其余 finding 可以删除。

## 判断与下一步

材料选择有继续研究价值，但目前不值得直接增加一次独立 LLM 调用：收益尚未经过质量与总耗时验证。优先在现有大纲生成中试验输出每章需要的 finding_ids（允许跨章复用），程序合并图表必需 ID、验证引用完整性，未明确归属的材料保留。摘要、讨论、结论先保留全部研究结果。已有大纲缺少语义材料关联时仍保留全量，不靠图表放置位置推断删除。

后续需比较全量与候选的事实覆盖、数字与引用一致性、修订正确性，以及包含选材开销的端到端耗时，再决定是否接入。当前仅一个大样例，不外推所有任务。

814 项测试及 4 项 subtests 通过，覆盖公共 Writer、基础写作、F5 大纲/正文/修订/导入和其他 Writer 调用方。新增 10 项阶段规则测试，验证原始任务不被修改、请求及有效约束保留、阶段规则分离和已选审稿意见传递。两处 Git diff --check 通过。本轮未修改 F1—F4/F6；工作区原有相关改动保留。
